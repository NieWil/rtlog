# Working on rtlog

Instructions for coding agents (Claude Code, Codex, Cursor, Copilot) and a short version for people. [CONTRIBUTING.md](CONTRIBUTING.md) is the human guide; [docs/spec.md](docs/spec.md) is the contract.

rtlog is a deferred logger. A log call writes a few binary bytes into a per-thread lock-free ring; a drain sends the frames out; the host decodes them to text, JSON lines or Perfetto. Its promise: **a log call does not disturb the program it observes.**

## Layout

| Path | What |
| --- | --- |
| `crates/rtlog` | The library (`no_std`; `std` feature: thread-local rings, drain thread, crash handler). Hot path: `ring.rs`, `arg.rs`, `level.rs`, `clock.rs`, `runtime.rs::__local_emit`. |
| `crates/rtlog-decode` | Host decoder library and the `rtlog` CLI (`src/bin/rtlog.rs`). |
| `c/include/rtlog.h` | Single-header C/C++ implementation, same wire format. `c/zephyr`: Zephyr module. |
| `examples/` | Runnable examples (not published). `size/mcu`: Cortex-M4F size firmware. |
| `scripts/` | `spec_check.py` (spec rules), `c_e2e.sh` (C end-to-end), `size_report.py`, demo `run.sh`. |
| `docs/` | Guides, `spec.md` (what is built), `roadmap.md` (what is not), `implementation.md` (deviations). |
| `results/` | Timing results from users' boards, one file per board and version. |

## Before you call a change done

Run what CI runs for the parts you touched. All must pass; none may be loosened to get green.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps   # every public item documented
cargo test --workspace
cargo build -p rtlog --no-default-features --target thumbv7em-none-eabihf --release   # no_std
python3 scripts/spec_check.py                                  # real-time, wire, usability rules
scripts/c_e2e.sh gcc g++                                       # if c/ or the wire format changed
cargo llvm-cov --workspace --summary-only                      # line coverage must stay >= 97 %
cargo deny check && typos && actionlint && shellcheck scripts/*.sh scripts/demo/*.sh
```

For a change to `crates/`, `c/`, the wire format, the log macros or the docs, also apply the **rtlog-spec-check** skill: [`.claude/skills/rtlog-spec-check/SKILL.md`](.claude/skills/rtlog-spec-check/SKILL.md). Claude Code loads it automatically; other agents should read it and follow its three steps (run the checker, review what it cannot see, report).

## Rules that are easy to break

- **Hot path:** nothing a log call reaches may allocate, lock, format, do I/O, make a syscall, panic or sleep. A full ring drops and counts; it never waits. New hot-path functions go into `HOT_PATH` in `scripts/spec_check.py`.
- **Budgets are in cycles** (spec section 10c), not nanoseconds. Size budgets on Cortex-M4F are hard limits.
- **Wire format:** a frame ID or argument tag is identical in `wire.rs`, `arg.rs`, `rtlog.h` and the decoder. Never reuse an ID; old captures must keep decoding. Add a test in `crates/rtlog-decode/tests/malformed.rs`.
- **Crash handler** (`crash.rs`, `rtlog__on_signal`): async-signal-safe only. No allocation, `try_lock` only, `open`/`write`/`close`.
- **`no_std`:** nothing outside the `std` feature may need `alloc`.
- **Versions:** the workspace version and the exact `rtlog = { version = "=X.Y.Z" }` pin in `crates/rtlog-decode/Cargo.toml` change together (see [docs/releasing.md](docs/releasing.md)).
- **Tests:** never skip, ignore or weaken a test to make CI pass. Fix the cause. A flaky test is a bug to root-cause.

## Writing docs and changelog

- Update `README.md` or the guide in `docs/` that covers the change, and add a line to `CHANGELOG.md` under `## Unreleased`.
- `docs/spec.md` describes only what is built. Plans go in `docs/roadmap.md`; a deliberate deviation goes in `docs/implementation.md`.
- Plain, concrete sentences. Numbers with their unit and the conditions they were measured under (CPU, clock, build profile). No marketing words ("blazing", "seamless", "robust").
- Every public Rust item has a doc comment (CI fails otherwise).

## Commits and pull requests

- One topic per pull request. The description says why, what changed and which checks ran, with their results.
- Do not commit generated files except `results/README.md` (regenerated by `scripts/results.py`) and lockfiles.
